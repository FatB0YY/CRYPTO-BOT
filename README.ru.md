# DEXONIR

Арбитражный бот, отслеживающий разницу цен по одним и тем же парам токенов между децентрализованными биржами в сети Solana и централизованной биржей, и совершающий сделки, когда спред покрывает собственные издержки.

## Задача

Одна и та же пара торгуется на разных площадках по слегка отличающимся ценам. Забрать эту разницу звучит просто и обычно таковым не является: пока ордер доходит, спред успевает сдвинуться, а то, что на бумаге выглядело прибыльным, часто целиком съедается комиссиями.

Поэтому бот явно разделяет два числа:

- **Gross** — валовая прибыль по разнице цен между Raydium и Bybit, без учёта издержек
- **Net** — то, что остаётся после всех комиссий с обеих сторон: комиссии пула Raydium, приоритетной комиссии Solana и торговой комиссии Bybit

Значение имеет только net. Крупный валовый спред на неликвидном пуле с высокой комиссией — это убыточная сделка, и вся логика построена вокруг этого различия, а не вокруг поиска спредов как таковых.

## Площадки

| Площадка | Тип | Роль |
| --- | --- | --- |
| **Raydium** | DEX в Solana | Поиск пулов, расчёт и исполнение свапов |
| **Meteora** | DEX в Solana (DLMM) | Цены из активного бина, состояние позиций |
| **Bybit** | Централизованная биржа | Живые цены по WebSocket, рыночные ордера |

## Как это работает

**Выбор пула.** `getPopularRaydiumTokens` собирает уникальные токены из топ-50 пулов Raydium по суточному объёму, `getTopRaydiumPoolByTokens` выбирает наиболее ликвидный пул для конкретной пары. Именно ликвидность определяет, торгуем ли спред в принципе, поэтому выбор пула идёт раньше сравнения цен.

**Источники цен.** Цены Bybit приходят по WebSocket-подписке на отслеживаемые пары, категория инструмента (spot, linear) определяется для каждого символа автоматически. Цены Meteora читаются из активного бина DLMM-пула.

**Расчёт до отправки.** `getComputeSwapBase` вычисляет параметры предполагаемого обмена, ничего не отправляя в сеть, — сделка оценивается по реальному ожидаемому выходу, а не по средней цене. `getRaydiumSwapFeePercent` даёт комиссию пула, `getPriorityFees` — текущую приоритетную комиссию Solana; оба значения идут в расчёт net.

**Исполнение.** `postTransactionSwap` запрашивает у API Raydium подписываемые транзакции, `signAndSendTransactions` подписывает и отправляет их в сеть. `ensureTokenAccount` создаёт Associated Token Account для токена, если его ещё нет на кошельке, — без этого шага транзакция просто не проходит.

**Кошельки и балансы.** `getWalletsFromEnv` читает ключи Solana, Solflare и Metamask из окружения, проверяет их наличие и приводит каждый к формату, который ожидает соответствующий SDK. Перед циклом проверяются балансы в Solana, в EVM-сетях и на аккаунте Bybit.

## Переменные окружения

### Кошельки

| Переменная | Описание |
| --- | --- |
| `WALLET_SOLANA_KEYGEN_SECRET_KEY` | Секретный ключ Solana, созданный через `solana-keygen`, в виде JSON-массива байт |
| `WALLET_SOLFLARE_SECRET_KEY` | Секретный ключ кошелька Solflare, в виде JSON-массива байт |
| `WALLET_METAMASK_PUBLIC_KEY` | Публичный ключ Metamask, для EVM-сетей |

### Биржа и RPC

| Переменная | Описание |
| --- | --- |
| `API_KEY_BYBIT` | API-ключ Bybit |
| `API_SECRET_BYBIT` | Секретный ключ Bybit |
| `ANKR_RPC_URL` | RPC-эндпоинт Ankr |
| `ANKR_API_KEY` | API-ключ Ankr, если используются авторизованные запросы |
| `TX_VERSION` | Версия транзакции — `V0` или `LEGACY` |

Две из этих переменных — приватные ключи с прямым доступом к средствам. Держите `.env` вне системы контроля версий.

## Стек

TypeScript, Node.js, Raydium SDK v2, Meteora DLMM SDK, API и WebSocket Bybit, Ankr RPC, Jest, ESLint, Prettier.

## Запуск

    git clone https://github.com/FatB0YY/CRYPTO-BOT.git
    cd CRYPTO-BOT
    npm install

Создайте `.env` на основе `.env.example`, заполните переменные выше и запустите:

    npm run start

Тесты:

    npm run test
